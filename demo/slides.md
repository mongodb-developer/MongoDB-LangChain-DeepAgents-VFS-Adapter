# `deepagents_mongodb_fs`
### MongoDB Atlas-backed virtual filesystem for LangChain DeepAgents

**Product check-in** · v0.1.0 (late-beta)

---

## The problem we set out to solve

DeepAgents needs to navigate **large, evolving document corpora** living in S3 — `ls`, `glob`, `grep`, `read`, `write`, `edit` — but:

- S3 alone gives you **no search**: no semantic, no full-text, no ranking
- Building an index per agent run is wasteful and slow
- Naïve embeddings-only systems miss exact identifiers; naïve keyword-only systems miss paraphrase

We need **hybrid search** over an **always-fresh index**, with **S3 as the source of truth**.

---

## What we ship today

A drop-in `BackendProtocol` implementation that wires a DeepAgent to:

- **S3** for content (read/write/edit/upload/download, ETag-conditional)
- **MongoDB Atlas** for search (chunks + vector + full-text indexes)
- A **background watcher** that keeps the index in sync (polling or SQS)
- **Hybrid `grep`** via `$rankFusion` (RRF over FTS + vector search)
- A **stable error taxonomy** so failures never leak as stack traces

→ Engineers integrate in ~10 lines. Agents get production search out of the box.

---

## Architecture in one diagram

```
DeepAgent
   │
   ▼
MongoFilesystemBackend ───► S3 Backend          (read/write/edit, pass-through)
       │
       ├──► SearchRouter ──► MongoDB Atlas      (ls / glob / grep)
       │                       ▲
       │                       │
       └──► InitialSync + Watcher
            (Chunker → Embedder → bulk upsert)
```

Constructor returns **immediately**. Sync + index provisioning run in a daemon thread; search calls block on a `_ready` event until the first pass completes.

---

## Why `$rankFusion`? (the technical bet)

Two retrieval signals over the same chunk corpus:

| Signal | Strength | Weakness |
|---|---|---|
| **Full-Text Search** (BM25) | Exact terms, identifiers, rare strings | Misses paraphrase |
| **Vector Search** (cosine) | Semantic / paraphrased queries | Misses exact tokens |

Their scores are **incomparable** → we use Atlas `$rankFusion` (Reciprocal Rank Fusion), 50/50 weighted, server-side, single round trip.

**Three-tier graceful degradation:** Atlas+embedder → text-only → plain `$regex`. Same code path runs on production and CI.

from deepagents_mongodb_fs import MongoFilesystemBackend

backend = MongoFilesystemBackend(

## Plugging into LangChain DeepAgents

Our `MongoFilesystemBackend` implements DeepAgents' `BackendProtocol`, so it drops straight into `create_deep_agent()` as the `backend` argument — **no shim, no adapter, no fork.**

```python
from deepagents import create_deep_agent
from deepagents_mongodb_fs import MongoFilesystemBackend

backend = MongoFilesystemBackend(
    s3_bucket_name="acme-docs",
    mongodb_connection_string=os.environ["MONGODB_URI"],
)

agent = create_deep_agent(
    tools=[...],
    instructions="You are a research assistant over the ACME docs corpus.",
    backend=backend,          # ← our package goes here
)

agent.invoke({"messages": [{"role": "user", "content": "Summarize the ACME-AUTH-7421 incident."}]})
```

The agent's built-in `ls` / `glob` / `grep` / `read` / `write` / `edit` tools now transparently run against S3 + Atlas. See `docs/DEEPAGENTS_USAGE.md` for the full integration recipe.

## Consumer experience — what the agent (and its user) feels

A DeepAgent over our backend gets these calls for free:

- `ls("docs/")` — sub-second directory listing over Atlas
- `glob("**/*.pdf")` — wildcard search via Atlas search
- `grep("paraphrased question")` — hybrid lexical + semantic ranking
- `read / write / edit` — direct S3 with ETag conflict detection
- **Live sync**: drop a file in S3 → searchable within polling interval

**The hero moment:** three `grep` queries, same corpus — lexical wins, semantic wins, hybrid wins all three.

## Roadmap — performance & scale milestone

**Single dataset, three tiers.** English Wikipedia full dump:

| Tier | Scale | What it proves |
|---|---|---|
| CI smoke | 1 K articles | Pipeline correctness |
| Pre-release | 100 K articles | `InitialSync` 16-worker fan-out, embedder retry path |
| Stress | 6.9 M articles, ~90 GB | Atlas index size, rate-limit headroom, watcher churn under hourly incremental dumps |

Free labeled query sets (NQ / TriviaQA / HotpotQA / MS MARCO) → measurable **recall / nDCG** for `$rankFusion` vs. text-only vs. vector-only.
